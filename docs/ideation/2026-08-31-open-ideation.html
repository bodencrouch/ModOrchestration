Grounding Context

Codebase context. ModSync is a .NET 9 + Avalonia installer for Star Wars: KOTOR. Core owns instructions, the virtual file system, and Holo / Ody / KPatcher engines. The GUI is a wizard. Tests live in one project. The live contract this week is to prove mod-builds/content/k{1,2}/full.md installs identically to a literal human run. Instruction paths must use <<modDirectory>> / <<kotorDirectory>>. Validation uses the virtual file system. Install order is load-bearing: loose files are last-writer-wins, and patchers bake 2DAMEMORY row indices into .ncs. Exit code 0 is not proof. This week’s dirty Core includes Unix NSS recovery, ArchiveResolver, dangling 2DA rows, and Linux Holo InfoName / .rte work.

Pain and leverage. Silent-wrong steps survive because a heartbeat looks like a result. Linux Holo can hang on CWD, Tk dialogs, or ctypes.windll. Ody rejects --flag=value. DryRun models classic game-directory destinations and does not simulate managed hardlink staging. The README says the installer does not download; the wizard and agent playbook already do. Leverage already sits in install --direct-markdown, checkpoints, ledgers, the shared validation pipeline, and scripts such as cli_validate and diff_manual_vs_auto.

Past learnings. docs/solutions holds agent-guidance layering (one home per fact) and the manual-release workflow. It does not yet hold installer-domain findings. GitHub Releases stay manual.

External context. TSLPatcher is the community oracle. Holo --validate is INI / config syntax, not content equality. KotorDiff (PyPI 2025) differs GFF / 2DA / TLK / ERF and falls back to SHA256 for NCS. Adjacent patterns: Wabbajack compile-from-golden, Vortex Replicate, WeiDU weidu.log, ME3Tweaks MixIns + hash. The useful compiler analogy is gcc versus clang: compare the resource AST, not packed ERF bytes.

Additional context. STRATEGY.md (2026-07-13) still frames encode-on-Holo-CLI and multi-author publish. The live bar this week is twelve-tree full.md parity, not that publish track.

1. Witness PASS type

Confidence 85% Complexity High

Make one Core type the only green light. A step is not a pass because a child exited 0. It is a pass when the patcher log is clean, the scoped tree actually changed, the change sits inside the step’s claim, and a format-aware resource differ (GFF / 2DA / TLK / ERF; SHA256 only for NCS) agrees. Packed ERF or TLK byte drift is a packing dissent, not a fail, and only after semantic equality is proved. Holo --validate stays an INI check. Optional later: a two-engine resource vote as a published verdict, not as a fourth mystery engine.

Description
Productize D7 and the mission’s semantic-compare rule as one type consumed by CLI, ValidatePage, Installing, and diff_manual_vs_auto.
Basis
direct: CONTRIBUTING.md writes a ledger pass only after the mutation matches the step’s claim. direct: unified-install-parity-mission.md: verify patcher success from logs and resulting resources, not process exit. Compare loose resources by identity and ERFs by contained resources; packing-only byte diffs are acceptable only after semantic equality. external: KotorDiff as the format-aware differ; Holo --validate is ValidateConfig, not equality.
Rationale
Twelve-tree nights already pay for this judgment by hand. Until PASS is a type, every engine, script, and wizard page can invent a shorter beep.
Downsides
Needs a Core equality kernel and per-step expected-delta discipline. Some packing-only diffs will stay noisy until the differ is trusted. Does not by itself fix hanging children or wrong archives.

2. DryRun identity split

Confidence 80% Complexity Medium

Stop selling one green badge for two predicates. The virtual file system answers “is this plan well-typed?” — placeholders, wildcards, missing archives, classic destinations. It does not answer “what will install do?” when managed staging or hardlink snapshots are in play. Proof is a disposable hardlink clone on the real filesystem, or an explicit refusal to claim install equality. ValidatePage and cli_validate must not share a single green with apply.

Description
Name the tree DryRun did not simulate as a first-class result. Keep VFS. Do not grow it into a second universe that pretends to be hardlink physics.
Basis
direct: docs/knowledgebase/validation-pipeline.md: DryRun models classic destinations under <<kotorDirectory>> and does not simulate profile staging roots or hardlink deploy. direct: docs/knowledgebase/modbuild-paranoia-doctrine.md: ext4 hardlink snapshots are effectively free. reasoned: a second simulated world will keep missing the fixture (the jig) that real writes go through.
Rationale
Parity U4 already states the split. The product still shows one green. That is how “validate passed” becomes D7’s cousin.
Downsides
Hardlink proof costs disk and time versus a VFS walk. Copy must change so users are not promised a dress rehearsal. Deleting VFS entirely is out — the sandbox rule still requires it for analysis.

3. Guide-as-source + digest expiry

Confidence 78% Complexity Medium

Treat content/k{1,2}/full.md as the living source, an IR as what Core executes, and KOTOR*_Full.toml as a compile cache you can delete. Stamp every TOML run with guide hash + ingest commit. The comfortable GUI/CLI path loads the guide. A prebuilt full TOML is a labeled fixture that cannot be a reference install. STRATEGY’s “instruction file stays the single source of truth” and its Full.toml pass-rate metric are the thing being retired, not papered over.

Description
Put D1a on the default load/install surface. Emission becomes decompile. Agents stop validating a drifted fixture because it was the easy click.
Basis
direct: unified-install-parity-mission.md supersession 1: a current content/k1/full.md or content/k2/full.md is the authority; prebuilt KOTOR*_Full.toml files are fixtures or diagnostics only. direct: STRATEGY.md still calls the instruction file the single source of truth and still metrics full-build pass rate against those TOMLs.
Rationale
The mission and STRATEGY are two products. Picking “guide is source” collapses convert / ingest / round-trip into a compiler story.
Downsides
Breaks muscle memory for anyone who still launches from Full.toml. Requires an IR story so Markdown is not executed as ad-hoc string soup. Does not by itself teach unknown sentence forms (see idea 7).

4. Generation store

Confidence 72% Complexity High

Promote “restore snapshot before N, fix, replay N onward in guide order” from prose into the only legal motion of the game tree. Step N writes generation N as a hardlink copy-on-write of N−1 plus that step’s writes. The kotor directory is a pointer. Rollback is retargeting the pointer, then verifying hash identity. Append-at-end becomes unrepresentable: there is no live tree to tack a missed step onto. Hardlinks must break on first write so a snapshot cannot be mutated through a shared inode.

Description
Checkpoints and paranoia snapshots already assume this is cheap. Make it the store, not an operator ritual, and refuse write-through hardlinks.
Basis
direct: AGENTS.md: if step N fails you may not install it after N+k; restore the snapshot taken before N and replay onward. Measured 2026-08-05: 103 files differing and 59 removed after append-at-end. direct: manual-parity-testing-methodology.md: an in-place write through a hardlink changes the snapshot too. direct: k1-oneshot-parity-spec.md: never compare a tree that continued past a failure to K1_manual.
Rationale
Order is physics because one tree is mutated. If the tree cannot be mutated in place, the destructive protocol is a pointer move, and last-writer inversion cannot land on “current” without a new generation.
Downsides
Rewrites InstallationService, managed deploy, and the Installing page. Disk multiplies with generation count unless old gens are pruned. “Infinite git of every write” is a later extreme, not this idea.

5. Honest download product

Confidence 80% Complexity Medium

The public contract and the running product disagree. README says the installer does not download and that archives must already sit in one folder. The wizard’s Fetch Downloads step, nxm://, and the headless playbook already do Nexus / MEGA / CAPTCHA work. Pick one product and say it in both places: either a declared acquire phase with typed failure classes (stale DeadlyStream id, Nexus Turnstile, MEGA needs a browser, HTML saved as .rar), or a hard stop that matches the README and keeps fetch outside Core.

Description
End the dual-truth. The interesting object is the boundary — sealed, hashed, typed archives in <<modDirectory>> — not a new locker brand name.
Basis
direct: README.md: “First and foremost the installer does NOT download all required mods, it requires that all mods are downloaded, unextracted, to the same folder.” direct: STRATEGY.md still wants to remove the manual download-and-place chain and already ships nxm://.
Rationale
Operator time this week is often host walls, not install math. Users who believe the README get no help; users who believe Fetch Downloads hit a product that denies the job exists.
Downsides
Either choice is a product-identity vote. Making acquire official invites CAPTCHA and host policy into the installer. Evicting fetch means the GUI must stop offering it. This idea does not pick the side — it insists the sides stop pretending to be the same product.

6. Linux Holo child-process supervisor

Confidence 76% Complexity Medium

Linux Holo is not a quiet CLI. Invoked from the wrong CWD it can poll a wrong-but-existing path in a ~4ms loop with zero output. --console can still hang forever on an unhandled exception dialog. ModSync should own a supervisor: control CWD, bound silence, classify working / hung / dialog / dead, and never leave a human or agent watching an empty pipe. InfoName / .rte sanitizers stay; they are not a substitute for knowing the child is stuck.

Description
Ship hang and dialog classification before the next Linux full-build night. Engine-start receipts (parsed argv, first log line) belong here as preconditions, not as a separate “Ody equals-sign” product.
Basis
direct: CONTRIBUTING.md: wrong CWD polls forever with zero output and zero timeout; --console does not guarantee non-interactive operation. direct: Instruction.cs documents Linux Holo 1.5.1 importing rte_editor.py on a .rte InfoName and calling ctypes.windll.
Rationale
This week’s dirty Core is a symptom. The recurring pain is an unattended child that can look busy while doing nothing.
Downsides
Dialog detection on Linux is messy. A supervisor does not replace owning patcher semantics. Treating “never invoke Holo” as the idea overclaims the rte_editor quote.

7. full.md sentence-form grammar

Confidence 70% Complexity High

Lift the surveyed instruction forms — option / namespace, delete, cross-mod conditional, run-patcher-N-times, rename / copy-as, overwrite guidance — into a versioned grammar that --direct-markdown must accept or fail closed. An unknown sentence is a parser bug, not a silent skip. GuideDirective then binds to forms, not an over-wide verb library. STRATEGY’s multi-author track becomes “markdown that uses these forms,” not another convert special-case.

Description
Make ingestion an ISA. Convert gaps (NPC Clothing, HQ Blasters, and the rest) pay the same parser instead of accumulating one-off coalesces.
Basis
direct: docs/knowledgebase/k1-oneshot-parity-spec.md: if a guide sentence cannot currently be turned into an instruction, the parser must learn that sentence form. The top three forms — option selection, deletion, and cross-mod conditionals — carry most of the risk.
Rationale
Idea 3 makes the guide the source. This idea is how a source stays executable as authors write new sentences. Without it, “guide is authority” is a policy that still silently drops prose.
Downsides
A closed grammar is a long ingest project. Fail-closed will halt runs that today limp through. Does not replace archive identity or PASS.
